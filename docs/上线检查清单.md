## 10. 现有取舍

- 数据库是 **SQLite 单文件**：单机够用，但没有并发写扩展性；将来要多实例要换 PostgreSQL / MySQL。
- gunicorn 目前是 `--workers 1 --threads 4`：社团规模够用，流量上来再调。
- 前端 nginx 与后端同机：成本低，但一起挂；重要性变高后再考虑分离。

## 11. 服务器首次构建的依赖源

✅ **已支持**：三个 Dockerfile 都接受带默认值的构建参数，默认仍是官方源（行为不变），
网络受限时在 `.env` 里填国内镜像即可：

```bash
# 服务器 .env 加两行（本地 .env.local 已经加好）
PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
NPM_REGISTRY=https://registry.npmmirror.com/
```

实现方式：`Dockerfile.backend` 用 `ARG PIP_INDEX_URL` + `pip install --index-url "$PIP_INDEX_URL"`；
`Dockerfile.frontend` 与 `Dockerfile.frontend.prod` 用 `ARG NPM_REGISTRY` + `npm ci --registry="$NPM_REGISTRY"`；
两个 compose 文件的 `build.args` 负责透传。

实测：清华 PyPI 源构建后端镜像约 1 分钟；npmmirror 源前端 `npm ci` 12 秒装完 52 个包
（走官方源时单个请求就要 20-30 秒）。
