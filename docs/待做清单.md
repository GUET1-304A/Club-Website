**难度：★★★☆☆** | 工作量：3~5 天 | 需集成外部 OCR API，但整体流程清晰

**需求来源：** 任务4 — 个人中心 + 证书智能识别录入模块

**当前状态：** ✅ 已完成 — 采用大模型视觉 API（DeepSeek-VL / Qwen-VL / GPT-4o 等 OpenAI 兼容视觉模型），
实现「上传图片 → AI 结构化识别 → 表单自动回填 → 人工修正 → 提交 → 管理端审核 → 自动归档成果库」完整闭环。
详见《证书智能识别与审核归档开发文档》。

#### 8.1 数据模型 ✅

- [x] `certificates` 表：member_id、name、level、category、winner、issuer、date、images、
  ocr_text（识别原文）、ocr_fields（结构化 JSON）、status（pending/verified/rejected）、
  review_note、reviewed_by、reviewed_at
- [x] `awards` 表新增 certificate_id，审核通过后自动生成 Award 记录（实验室总成果库）

#### 8.2 后端开发 ✅

- [x] `services/ocr_service.py`：`extract_fields()` 结构化字段提取（获奖名称/等级/类别/获奖人/颁奖单位/获奖时间/描述）+ 原文转录，
  容错解析 Markdown 围栏、等级归一化、非 JSON 响应降级为空字段
- [x] `POST /api/member/certificates/ocr`（未建证书直接识别图片，返回字段供表单回填）
- [x] `POST /api/member/certificates/<id>/ocr`（已保存证书重新识别并持久化 ocr_text/ocr_fields）
- [x] 管理端：`GET /api/admin/certificates`、`GET /api/admin/certificates/<id>`、
  `POST /api/admin/certificates/<id>/review`（通过 → 自动创建 Award + 站内通知；驳回 → 通知成员）
- [x] 成员修正被驳回证书后自动重新进入待审核（rejected → pending）
- [x] 格式校验（jpg/png/webp、单张 10MB、最多 5 张）+ 存储/OCR 错误容错

#### 8.3 前端开发 ✅

- OCR 需要配置视觉模型：`OCR_ENABLED=true` + `OCR_ENDPOINT/OCR_API_KEY/OCR_MODEL`

详见《CLI接口调用文档》。

#### 10.1 CLI 工具开发

- [x] 技术选型：Python Click（`python -m cli` 直接运行，无需安装）
- [x] 命令结构设计：
  ```
  python -m cli auth login        # 登录认证（统一认证，自动识别管理员/成员）
  python -m cli project list      # 项目列表
  python -m cli project create    # 创建项目（管理员）
  python -m cli task list --project=ID --mine   # 任务列表
  python -m cli task create       # 创建任务
  python -m cli task status ID --status done    # 任务状态流转
  python -m cli report submit     # 提交周报
  python -m cli report analyze    # AI 分析周报
  python -m cli report review     # 审阅周报（管理员）
  python -m cli award list        # 成果列表
  python -m cli award export      # 成果导出（json/csv）
  python -m cli member list       # 成员列表
  python -m cli config get/set    # 配置管理（管理员）
  python -m cli reminder create   # 创建提醒
  python -m cli notify list       # 站内通知
  ```

## 开发建议

1. **从简单到复杂推进：** 先完成 ★~★★ 任务（联系我们、公告、留言板、文档），积累开发节奏
2. **证书识别**可先接入百度 OCR（免费额度充足），快速验证流程，后续切换大模型视觉 API
3. **项目管理智能体**建议分三阶段：
   - 第一阶段：数据模型 + 项目/任务 CRUD + 看板视图
   - 第二阶段：周报系统 + 定时提醒
   - 第三阶段：AI 需求解析 + 周报分析
4. **CLI 接口**建议在项目管理 API 稳定后再开发，避免接口频繁变更
5. AI 功能建议统一封装为 `ai_service.py`，便于切换不同大模型提供商
