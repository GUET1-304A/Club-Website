# 个人中心证书 OCR 交互设计

## 目标

让已登录成员在个人中心的“证书管理”页面，对已上传图片的证书发起文字识别，并查看服务端持久化的识别结果。

## 交互与数据流

1. 每张证书卡片显示“识别文字”操作。没有证书图片时该操作禁用，并提示先上传图片。
2. 点击操作后，仅该证书进入加载状态，并调用 `POST /api/member/certificates/{id}/ocr`。
3. 服务端成功返回 `ocrText` 及更新后的 `certificate`；前端用响应更新该卡片，在卡片内提供可展开的“识别结果”区域。
4. 识别结果已经存在时，操作改为“重新识别”，仍保留现有结果，直到服务端成功返回新结果。

## 错误处理

- `not_configured`（503）：提示 OCR 尚未配置；不创建伪造文字，也不改写已有结果。
- 提供商请求失败（502）或网络异常：显示接口的真实错误信息；允许用户稍后重试。
- 无图片：不发送请求。

## 接口约定

- 前端请求函数：`memberRunCertificateOcr(certId)`。
- 返回类型：`{ success: boolean; ocrText: string; certificate: CertificateData }`。
- 认证沿用成员 JWT，后端继续验证证书归属。

## 验收

- 证书管理页面可见 OCR 操作，且未上传图片的证书不能发起识别。
- 成功识别后，页面无需刷新即可展示并保留文字。
- 未配置或失败时用户获得明确提示，且 TypeScript 检查、前端构建和后端测试通过。
