# 完整项目完善设计

## 目标

将 `worktree-final-prompt` 工作树完善为可构建、可本地 Docker 运行、可部署到生产环境的完整系统。覆盖公开站、管理端、成员门户、资源与证书能力、通知、OSS/OCR/AI 集成适配及生产运维材料。

真实第三方服务凭据尚未提供。本次实现完成其环境变量配置、服务适配、降级行为和验证路径；不提交任何真实密钥，不进行域名 DNS 变更、证书签发或生产数据迁移。

## 架构

浏览器访问 React/Vite 前端。开发环境由 Vite 将 `/api`、`/uploads` 与 `/health` 代理至 Flask；生产环境由 Nginx 统一提供前端静态资源、HTTPS 终止及 API 反向代理。

Flask 按 `/api` 前缀注册公开、管理员及成员蓝图，使用 JWT 分隔管理员与成员身份。SQLAlchemy 管理本地 SQLite 数据库；生产数据库连接通过环境变量注入。

文件、OCR 和 AI 均置于独立适配层：

- 未配置 OSS 时，文件保存至本地上传目录；已配置时，使用 OSS。
- 未配置 OCR/AI 时，相关 API 返回明确的 `not_configured` 状态和用户可见提示，不伪造业务结果。
- 已配置时，适配层调用指定提供商，并对超时、服务错误和无效响应返回统一错误格式。

## 分阶段交付

### 阶段 1：可运行基线

- 修复前端 TypeScript/JSX 编译问题和依赖安装可复现性。
- 修复 Docker 镜像、Compose 服务、健康检查与开发/生产环境变量模板。
- 为核心公开、管理员和成员 API 建立冒烟测试。

验收：前端生产构建通过；Docker Compose 可启动；`/health` 健康；核心 API 成功、未认证与校验失败路径均可验证。

### 阶段 2：成员与管理完整流程

- 完成统一登录/注册和成员登录，确保 JWT token 键及服务端身份一致。
- 验证并完善成员资料、密码、项目、里程碑、任务、资源、证书、通知与通讯录。
- 验证并完善管理端成员、项目、奖项、博客、页面、配置、申请、留言及导入导出。
- 统一前端加载、空状态、错误展示和权限失败处理。

验收：浏览器可完成管理员和成员登录、内容编辑、任务更新、文件上传、证书管理与通知已读等主要流程。

### 阶段 3：高级服务

- 实现文件存储服务的本地与 OSS 配置切换。
- 为 OCR 和 AI 提供商建立可替换适配接口、环境变量契约和安全降级。
- 为前端补充能力状态、等待状态和失败重试提示。

验收：无凭据环境不影响核心业务；模拟或真实配置环境可走到对应服务适配分支；错误和超时可预测且不泄露凭据。

### 阶段 4：生产交付

- 制作生产镜像与 Compose 覆盖配置。
- 配置 Nginx 反向代理、HTTPS 入口模板、数据与上传文件持久化、健康检查和重启策略。
- 提供 `.env` 模板、部署步骤、秘密清单、备份及回滚说明。

验收：新环境按文档可部署；应用可用健康检查监控；无真实凭据时可安全启动并标识可选服务未配置。

## 数据流与错误处理

1. 前端以 `/api` 为唯一业务入口；请求层添加 JSON 请求头和对应身份的 Bearer token。
2. Flask 鉴权后执行业务逻辑，返回稳定的成功对象或含 `error`、`message` 的失败对象。
3. 前端将网络错误、401/403、校验错误及服务未配置状态映射为可见提示。
4. 上传、OCR 和 AI 请求先检查服务配置；配置缺失时返回可识别状态，避免执行半完成操作。

## 测试策略

- 前端：TypeScript 构建、静态检查与关键请求层/路由检查。
- 后端：Flask 测试客户端覆盖公开、管理员、成员和集成降级路径。
- 集成：Docker Compose 启动后进行健康检查和主要 API 冒烟。
- 浏览器：验证登录、项目/任务、资源上传、证书、通知及管理端编辑。

## 安全与运维约束

- 所有密钥仅来自运行环境变量或部署平台秘密管理；不写入仓库、镜像或日志。
- 生产环境关闭调试模式，使用强随机 Flask/JWT 密钥，限制 CORS 来源。
- 上传限制类型和体积，保证文件路径安全。
- 真实凭据接入、域名与 DNS、TLS 证书签发和生产数据迁移需单独授权后执行。
