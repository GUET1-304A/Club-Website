## 二、一键更新（推荐）

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\deploy-prod.ps1
```

脚本会依次做：

1. 检查有没有未提交的已跟踪改动（有就停下）
2. `git push origin main`
3. `git archive` 打包当前 HEAD
4. 用 Workbench CLI 上传到服务器 `/tmp/`
5. 解压到 `/srv/304aistudio`
6. `docker compose ... up -d --build`
7. 检查首页和 `/api/config` 是否返回 200

如果已经手动推送过，可以加 `-SkipPush`。

## 三、手动更新（四步）

### 1. 本地提交并推送

```powershell
git status
git add <改动的文件>
git commit -m "feat: ..."
git push origin main
```

### 2. 打包当前提交

```powershell
git archive --format=tar.gz -o "$env:TEMP\shetuanweb-src.tar.gz" HEAD
```

### 3. 上传到服务器

```powershell
& "C:\Users\wy339\AppData\Local\Programs\workbench\workbench.exe" `
  upload "$env:TEMP\shetuanweb-src.tar.gz" /tmp/ `
  -i i-0jlhp604zk2b4ddh7683 -r cn-wulanchabu -f
```

### 4. 解压并重建

```powershell
& "C:\Users\wy339\AppData\Local\Programs\workbench\workbench.exe" `
  exec -r cn-wulanchabu -i i-0jlhp604zk2b4ddh7683 --timeout 900 `
  --command "cd /srv/304aistudio && tar xzf /tmp/shetuanweb-src.tar.gz -C /srv/304aistudio && docker compose -p 304aistudio -f docker-compose.prod.yml -f docker-compose.prod.tls.yml up -d --build"
```

生产镜像把代码打进镜像，没有开发环境那种挂载，所以**必须带 `--build`**，只 `restart` 不会生效。

## 五、回滚

代码回滚：找到上一个可用提交，重新打包那个提交并按上面第 3、4 步部署。

```powershell
git log --oneline -10
git archive --format=tar.gz -o "$env:TEMP\shetuanweb-src.tar.gz" <commit>
```

数据回滚：生产每天 03:00 自动备份，保留 14 天。

- 脚本：`/usr/local/bin/backup-304aistudio.sh`
- 备份目录：服务器 `/root/backups/304aistudio/`
- 升级前如涉及数据结构变化，先手动跑一次备份，再部署。

## 七、常见坑

1. **不要在服务器上 `git clone` / `git pull`**：服务器访问 GitHub 不通。
2. **不要提交** `.env`、`secrets/` 下的真实密钥、`deploy/certs/`。
3. `git archive` 解压只覆盖文件，**不会删除**仓库里已删掉的文件；如果这次真的删了文件，需要在服务器上手动删。
4. Compose 会自动读取 `/srv/304aistudio/.env`，命令里不需要再写 `--env-file`。
5. 服务器拉取依赖走国内镜像：pip 用清华源，npm 用 npmmirror；基础镜像已在本地，不要清空 Docker 镜像缓存。
6. 前端是 Vite 构建的 SPA，Nginx 直接托管静态文件；更新后浏览器强刷一次即可，没有 CDN。
7. 后台配置改动不需要重新部署，保存后会写数据库；但浏览器需要刷新才能读到新配置。
