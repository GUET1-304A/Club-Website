## 四、正式更新

仅在正式发布窗口获授权后，在本地执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy-prod.ps1
# 已手动推送过时可以加 -SkipPush；它不会跳过任何发布门禁。
```

流程：本地完整门禁 → 固定提交归档/推送/唯一文件上传 → 远端SHA256校验 → 独立`releases/SHA-token/` → 验证现有业务路径/挂载 → 版本镜像构建 → 停单一后端写入者创建备份并恢复演练 → 启动/健康检查 → 服务端与操作者网络HTTP版本验收。

只有服务端验收成功才原子更新`current-release`，之前的指针保存在`previous-release`。失败不自动覆盖或回滚数据。禁止直接解压覆盖安装根目录、手工compose更新跳过门禁、仅restart代替构建、猜卷名或删除业务卷。

当前是第一次从旧流程升级，`current-release`尚不存在；新发布会保存旧后端/前端镜像ID。旧Compose文件、镜像、运行秘密与证书须保留。不要使用`-FirstDeploy`绕过已有容器或数据卷。
